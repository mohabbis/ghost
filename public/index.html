Workflow capture · Human approval · Verified execution

Let agents act without giving them unchecked control.

Ghost records browser workflows, compiles them into typed steps, and runs them through a controlled execution pipeline. Sensitive actions pause for a human. Completed steps are verified, logged, and recoverable when a workflow defines a reversal.

Execution flow

Capture → Review → Approve → Execute → Verify → Recover

Models can propose work. Deterministic code decides what requires approval and what the worker may execute.

  1. 1

    Capture

    The Chrome extension records navigation, clicks, inputs, selections, submissions, and SPA route changes.

  2. 2

    Review

    A deterministic compiler converts the trace into editable, typed steps. Secret values are never recorded.

  3. 3

    Approve

    Send, pay, delete, submit, and other sensitive steps stop for a human decision.

  4. 4

    Execute

    The worker runs approved browser steps with Playwright and resumes from the execution journal after a pause or restart.

  5. 5

    Verify

    Assertions and screenshots record what happened. Run and approval events append to a per-organization hash chain.

  6. 6

    Recover

    Operators can retry, skip, cancel, or run defined compensation steps in reverse order.

Current repository

What is implemented.

The active product is the cloud application under cloud/, with a browser recorder under apps/extension.

  • Browser recording and deterministic compilationManifest V3 recorder, structured trace schema, secret redaction, and trace-to-step compilation without a required model call.
  • Playwright execution engineSemantic locators, typed steps, screenshots, assertions, and browser-session restore after approval.
  • Human approval controlsA deterministic classifier gates sensitive actions. Optional separation of duties prevents the requester from approving the same run.
  • Durable run stateAn append-only execution journal tracks completed work so retries and worker restarts do not blindly replay prior steps.
  • Verification, audit, and artifactsPer-step evidence, hash-chained audit events, local or S3 artifact storage, presigned access, and configurable artifact retention.
  • Agent interfacesHTTP and MCP tools can list, preview, and start runs. Approval remains in Ghost.
  • Operational toolingPostgres, Redis, BullMQ, structured JSON logging, Docker deployment, and optional Sentry error reporting.
  • Still earlyBrowser execution is the main path. Broader API connectors, stronger external audit anchoring, extension permission scoping, and production hardening remain active work.

Architecture

Cloud application, worker, recorder, and agent tools.

A modular stack for recording, reviewing, executing, and auditing workflows.

Web

Next.js · Auth.js · organization-scoped routes

Worker

Node.js · BullMQ · Playwright · structured logging

Core

Prisma · Postgres · Zod · execution journal · audit chain

Recorder

Chrome Manifest V3 · accessible locators · local buffering

Agent

HTTP API · MCP stdio · scoped tokens · no self-approval

Storage

Redis queue · disk or S3 artifacts · retention jobs

Use cases

Repeated work where mistakes have a cost.

Ghost is designed for operations teams moving structured work across browser-based systems.

Cross-system operations

Order entry, reconciliation, reporting, document processing, and administrative workflows.

Sensitive actions

Workflows that can prepare a submission or payment but must stop before committing it.

Reviewable evidence

Teams that need screenshots, assertions, approvals, and a clear event history after a run.

Boundaries

What Ghost is not.

Not a chatbot wrapper Not a blind macro recorder Not unsupervised execution Not agent self-approval
